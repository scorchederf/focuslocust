  \ of breaking down data, such as text, into smaller, manageable pieces called _tokens_. Each token is then assigned a unique\
  \ numerical identifier (ID). This is a fundamental step in preparing text for processing by machine learning models, especially\
  \ in natural language processing (NLP).\n\n> [!TIP]\n> The goal of this initial phase is very simple: **Divide the input\
  \ in tokens (ids) in some way that makes sense**.\n\n### **How Tokenizing Works**\n\n1. **Splitting the Text:**\n   - **Basic\
  \ Tokenizer:** A simple tokenizer might split text into individual words and punctuation marks, removing spaces.\n     -\
  \ _Example:_\\\n       Text: `\"Hello, world!\"`\\\n       Tokens: `[\"Hello\", \",\", \"world\", \"!\"]`\n2. **Creating\
  \ a Vocabulary:**\n   - To convert tokens into numerical IDs, a **vocabulary** is created. This vocabulary lists all unique\
  \ tokens (words and symbols) and assigns each a specific ID.\n   - **Special Tokens:** These are special symbols added to\
  \ the vocabulary to handle various scenarios:\n     - `[BOS]` (Beginning of Sequence): Indicates the start of a text.\n\
  \     - `[EOS]` (End of Sequence): Indicates the end of a text.\n     - `[PAD]` (Padding): Used to make all sequences in\
  \ a batch the same length.\n     - `[UNK]` (Unknown): Represents tokens that are not in the vocabulary.\n   - _Example:_\\\
  \n     If `\"Hello\"` is assigned ID `64`, `\",\"` is `455`, `\"world\"` is `78`, and `\"!\"` is `467`, then:\\\n     `\"\
  Hello, world!\"` → `[64, 455, 78, 467]`\n   - **Handling Unknown Words:**\\\n     If a word like `\"Bye\"` isn't in the\
  \ vocabulary, it is replaced with `[UNK]`.\\\n     `\"Bye, world!\"` → `[\"[UNK]\", \",\", \"world\", \"!\"]` → `[987, 455,\
  \ 78, 467]`\\\n     _(Assuming `[UNK]` has ID `987`)_\n\n### **Advanced Tokenizing Methods**\n\nWhile the basic tokenizer\
  \ works well for simple texts, it has limitations, especially with large vocabularies and handling new or rare words. Advanced\
  \ tokenizing methods address these issues by breaking text into smaller subunits or optimizing the tokenization process.\n\
  \n1. **Byte Pair Encoding (BPE):**\n   - **Purpose:** Reduces the size of the vocabulary and handles rare or unknown words\
  \ by breaking them down into frequently occurring byte pairs.\n   - **How It Works:**\n     - Starts with individual characters\
  \ as tokens.\n     - Iteratively merges the most frequent pairs of tokens into a single token.\n     - Continues until no\
  \ more frequent pairs can be merged.\n   - **Benefits:**\n     - Eliminates the need for an `[UNK]` token since all words\
  \ can be represented by combining existing subword tokens.\n     - More efficient and flexible vocabulary.\n   - _Example:_\\\
  \n     `\"playing\"` might be tokenized as `[\"play\", \"ing\"]` if `\"play\"` and `\"ing\"` are frequent subwords.\n2.\
  \ **WordPiece:**\n   - **Used By:** Models like BERT.\n   - **Purpose:** Similar to BPE, it breaks words into subword units\
  \ to handle unknown words and reduce vocabulary size.\n   - **How It Works:**\n     - Begins with a base vocabulary of individual\
  \ characters.\n     - Iteratively adds the most frequent subword that maximizes the likelihood of the training data.\n \
  \    - Uses a probabilistic model to decide which subwords to merge.\n   - **Benefits:**\n     - Balances between having\
  \ a manageable vocabulary size and effectively representing words.\n     - Efficiently handles rare and compound words.\n\
  \   - _Example:_\\\n     `\"unhappiness\"` might be tokenized as `[\"un\", \"happiness\"]` or `[\"un\", \"happy\", \"ness\"\
  ]` depending on the vocabulary.\n3. **Unigram Language Model:**\n   - **Used By:** Models like SentencePiece.\n   - **Purpose:**\
  \ Uses a probabilistic model to determine the most likely set of subword tokens.\n   - **How It Works:**\n     - Starts\
  \ with a large set of potential tokens.\n     - Iteratively removes tokens that least improve the model's probability of\
  \ the training data.\n     - Finalizes a vocabulary where each word is represented by the most probable subword units.\n\
  \   - **Benefits:**\n     - Flexible and can model language more naturally.\n     - Often results in more efficient and\
