  \ Class (USRCLS) defines a predefined set of authorities and system privileges for a user profile. It determines the user's\
  \ general role and access level within the system. However, a user class alone does not directly grant special authorities\
  \ (SPCAUT); instead, it serves as a guideline for assigning them.\n\nIn this example, we create a high-privilege user by\
  \ assigning them the `*SECOFR` (Security Officer) user class (USRCLS). By setting the special authority attribute (SPCAUT)\
  \ to `*USRCLS`, the system automatically grants the user all special authorities associated with the `*SECOFR` class.\n\n\

  \ authority controls user access to system objects (libraries, files, programs, etc.). It ensures security by defining what\
  \ users can do with specific objects.\n\n* `*ALL`: Full access (read, write, delete, execute).\n* `*CHANGE`: Modify but\
  \ not delete.\n* `*EXCLUDE`: No access.\n* `*USE`: Read-only or execute.\n* `*USERDEF`: Custom authority settings based\
  \ on a user's specific needs.\n\nSecure authority standard for users:\n\n* `USRCLS` should be `*USER`\n* `SPCAUT` should\
  \ be `*NONE`\n* `AUT` should always be `*EXCLUDE`\n* `*USRPRF` should have authority to itself\n* `*PUBLIC` should be `*EXCLUDE`\n\

  \ a user can perform on system resources. A user can be given one or more special authorities.\n\n* `*ALLOBJ` special authority:\

  \ to create, change, and delete user profiles.\n* `*JOBCTL` special authority: The Job control (`*JOBCTL`) special authority\
  \ allows a user to change the priority of jobs and of printing, end a job before it has finished, or delete output before\
