## Description

Adversaries may attempt to hide process command-line arguments by overwriting process memory. Process command-line arguments are stored in the process environment block (PEB), a data structure used by Windows to store various information about/used by a process. The PEB includes the process command-line arguments that are referenced when executing the process. When a process is created, defensive tools/sensors that monitor process creations may retrieve the process arguments from the PEB.[^4] [^1] <br><br>Adversaries may manipulate a process PEB to evade defenses. For example, [[kb/mitre/attack/techniques/T1055.012-process-hollowing|Process Hollowing]] can be abused to spawn a process in a suspended state with benign arguments. After the process is spawned and the PEB is initialized (and process information is potentially logged by tools/sensors), adversaries may override the PEB to modify the command-line arguments (ex: using the [[kb/mitre/attack/techniques/T1106-native-api|Native API]] `WriteProcessMemory()` function) then resume process execution with malicious arguments.[^5] [^1] [^2] <br><br>Adversaries may also execute a process with malicious command-line arguments then patch the memory with benign arguments that may bypass subsequent process memory analysis.[^3] <br><br>This behavior may also be combined with other tricks (such as [[kb/mitre/attack/techniques/T1134.004-parent-pid-spoofing|Parent PID Spoofing]]) to manipulate or further evade process-based detections.
