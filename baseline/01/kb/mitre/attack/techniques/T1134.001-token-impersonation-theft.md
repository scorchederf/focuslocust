## Description

Adversaries may duplicate then impersonate another user's existing token to escalate privileges and bypass access controls. For example, an adversary can duplicate an existing token using `DuplicateToken` or `DuplicateTokenEx`.[^1]  The token can then be used with `ImpersonateLoggedOnUser` to allow the calling thread to impersonate a logged on user's security context, or with `SetThreadToken` to assign the impersonated token to a thread.<br><br>An adversary may perform [[kb/mitre/attack/techniques/T1134.001-token-impersonation-theft|Token Impersonation/Theft]] when they have a specific, existing process they want to assign the duplicated token to. For example, this may be useful for when the target user has a non-network logon session on the system.<br><br>When an adversary would instead use a duplicated token to create a new process rather than attaching to an existing process, they can additionally [[kb/mitre/attack/techniques/T1134.002-create-process-with-token|Create Process with Token]] using `CreateProcessWithTokenW` or `CreateProcessAsUserW`. [[kb/mitre/attack/techniques/T1134.001-token-impersonation-theft|Token Impersonation/Theft]] is also distinct from [[kb/mitre/attack/techniques/T1134.003-make-and-impersonate-token|Make and Impersonate Token]] in that it refers to duplicating an existing token, rather than creating a new one.

| [S0154](https://attack.mitre.org/software/S0154) | Cobalt Strike | Cobalt Strike can steal access tokens from exiting processes.[^1] [^2]  |

| [S0367](https://attack.mitre.org/software/S0367) | Emotet | Emotet has the ability to duplicate the user’s token.[^1]  For example, Emotet may use a variant of Google’s ProtoBuf to send messages that specify how code will be executed.[^2]  |

| [[kb/mitre/attack/software/S0692-silenttrinity\|S0692]] | SILENTTRINITY | [[kb/mitre/attack/software/S0692-silenttrinity\|SILENTTRINITY]] can find a process owned by a specific user and impersonate the associated token.[^1]  |
| [S1011](https://attack.mitre.org/software/S1011) | Tarrask | Tarrask leverages token theft to obtain `lsass.exe` security permissions.[^1]   |
| [S1081](https://attack.mitre.org/software/S1081) | BADHATCH | BADHATCH can impersonate a `lsass.exe` or `vmtoolsd.exe` token.[^1]   |

| [S9033](https://attack.mitre.org/software/S9033) | Fooder | Fooder has used the `DuplicateTokenEx` API to duplicate the token of a specified process, and `CreateProcessAsUserA` to execute its payload.[^1]        |
| [S9036](https://attack.mitre.org/software/S9036) | LP-Notes | LP-Notes has impersonated the security context of the taskhostw.exe process via the `ImpersonateLoggedOnUser` API.[^1]  |

## Mitigations
| ID | Name | Description |
| --- | --- | --- |
| [[kb/mitre/attack/mitigations/M1018-user-account-management\|M1018]] | User Account Management | An adversary must already have administrator level access on the local system to make full use of this technique; be sure to restrict users and accounts to the least privileges they require.   |
| [[kb/mitre/attack/mitigations/M1026-privileged-account-management\|M1026]] | Privileged Account Management | Limit permissions so that users and user groups cannot create tokens. This setting should be defined for the local system account only. GPO: Computer Configuration > [Policies] > Windows Settings > Security Settings > Local Policies > User Rights Assignment: Create a token object. [^1]  Also define who can create a process level token to only the local and network service through GPO: Computer Configuration > [Policies] > Windows Settings > Security Settings > Local Policies > User Rights Assignment: Replace a process level token.[^2] <br><br>Administrators should log in as a standard user but run their tools with administrator privileges using the built-in access token manipulation command `runas`.[^3]  |
