## Description

Adversaries may clear system logs to hide evidence of an intrusion. macOS and Linux both keep track of system or user-initiated actions via system logs. The majority of native system logging is stored under the `/var/log/` directory. Subfolders in this directory categorize logs by their related functions, such as:[^1] <br><br>* `/var/log/messages:`: General and system-related messages<br>* `/var/log/secure or /var/log/auth.log`: Authentication logs<br>* `/var/log/utmp or /var/log/wtmp`: Login records<br>* `/var/log/kern.log`: Kernel logs<br>* `/var/log/cron.log`: Crond logs<br>* `/var/log/maillog`: Mail server logs<br>* `/var/log/httpd/`: Web server access and error logs

## Procedure Examples
| ID | Name | Use |
| --- | --- | --- |
| [S0279](https://attack.mitre.org/software/S0279) | Proton | Proton removes logs from `/var/logs` and `/Library/logs`.[^1]  |
| [S1016](https://attack.mitre.org/software/S1016) | MacMa | MacMa can clear possible malware traces such as application logs.[^1]  |
| [S1164](https://attack.mitre.org/software/S1164) | UPSTYLE | UPSTYLE clears error logs after reading embedded commands for execution.[^1]  |
| [S1206](https://attack.mitre.org/software/S1206) | JumbledPath | JumbledPath can clear logs on all devices used along its connection path to compromised network infrastructure.[^1]  |
